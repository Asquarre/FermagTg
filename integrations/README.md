# Автоматическая загрузка цен Fermag

Подготовленный адрес: `https://fermag.vercel.app/api/catalog-sync`.
Это **не подтверждение подключения**: сначала нужны публикация кода и настройка Vercel ниже.
Redis, входящее подключение в офисную сеть и доступ ноутбука разработчика к сетевой папке не нужны.

## Что получает айтишник

1. `integrations/Upload-Prices.ps1`.
2. Секретный файл `.catalog-sync/upload-config.json` — передать отдельно по защищённому каналу, не добавлять в Git, общий чат или общедоступную папку.
3. Путь к актуальному Excel в корпоративной сети. Учётная запись планировщика должна иметь доступ к этому пути и исходящий HTTPS на `fermag.vercel.app`.

Секрет создан командой `npm run catalog:prepare-sync`. Повторный запуск не меняет существующие ключи. Для замены ключа нужно согласованно заменить значение в Vercel и файле у айтишника.

## Формат Excel (согласовать перед первым запуском)

- Только `.xlsx`, до 2 МБ, не `.xls`, не CSV, не файл с паролем.
- На каждом листе: **A — код номенклатуры, B — название, C — цена в тенге**. Заголовки допустимы; название и название листа не используются для обновления.
- Коды должны точно совпадать с кодами сайта. Ведущие нули хранить текстом, а не числовой маской Excel. Код `0012` и `12` — разные товары.
- Цена: число от 0 до 1 000 000 000, до двух десятичных знаков. Формулы — только с сохранённым результатом; сервер их не вычисляет.
- В файле должны присутствовать **все коды текущего каталога сайта**. Лишние коды игнорируются. Пропущенные товары, неправильная цена или разные цены для одного кода отклоняют весь файл; старый прайс остаётся целым.
- Файл меняет только цены. Новые товары, названия, категории и фотографии по-прежнему добавляются в проект обычным способом.

Если корпоративная выгрузка устроена иначе, сначала нужен обезличенный образец: адаптер нельзя безопасно настраивать по догадке.

## Настройка Vercel владельцем сайта

1. В проекте **fermag** создать/подключить хранилище **Vercel Blob, Private** только к **Production**. Это постоянное файловое хранилище прайса, не Redis. Нужна серверная переменная `BLOB_READ_WRITE_TOKEN`.
2. В Settings → Environment Variables добавить **Secret** `CATALOG_SYNC_SECRET` только для **Production**. Значение — поле `key` из `.catalog-sync/upload-config.json`. Без префикса `REACT_APP_`.
3. Опубликовать изменения. Пока `CATALOG_SYNC_ENABLED` не задана, сайт продолжит использовать цены из Excel сборки; приём файла уже можно проверить.
4. Отправить первый файл и убедиться, что ответ HTTP 200 содержит `ok: true` и правильное `matchedProducts`.
5. Добавить `CATALOG_SYNC_ENABLED=true` только для Production и сделать Redeploy. Теперь `/api/catalog` и оформление заказа используют один и тот же сохранённый прайс. Если хранилище недоступно, новые заказы не подтверждаются по старым ценам; уже принятые заказы можно подтвердить без прайса.
6. Проверить на опубликованном сайте цены и корзину. Последующие выгрузки **не требуют Git push или пересборки**. Открытая страница проверяет цены раз в минуту, при возврате во вкладку и перед оформлением. При изменении суммы на отправке покупателя просят проверить её ещё раз.

В Preview и Development рабочий приём отключён; рабочие ключи и Blob не подключать к этим окружениям. Пока нет подключения и публикации, рабочая ссылка не готова к использованию.

## Запуск на Windows

Сохранить скрипт и конфигурацию, например в `C:\Fermag`. Ограничить чтение конфигурации администратором и учётной записью задачи.

```powershell
powershell.exe -NoProfile -File "C:\Fermag\Upload-Prices.ps1" -FilePath "\\SERVER\Share\Цены.xlsx" -ConfigPath "C:\Fermag\upload-config.json"
```

В Планировщике заданий запускать ежедневно после завершения выгрузки, при необходимости повторять каждый час. Повтор того же файла безопасен. Запускать от учётной записи с доступом к UNC-пути даже без входа пользователя. Назначить повтор задачи при ненулевом коде выхода, вести локальный журнал, уведомлять IT при постоянной ошибке. Компьютер должен быть включён в момент запуска.

Скрипт делает до трёх попыток одного снимка файла. HTTP 200 — данные сохранены, включая безопасный повтор (`unchanged: true`). HTTP 401 — неверный ключ; 409 — старый прайс/конфликт времени; 422 — файл не соответствует формату; 503 — конфигурация или хранилище недоступны. Скрипт не перенаправляет ключ на другой адрес.

`X-Catalog-Updated-At` — время изменения исходного файла в UTC. Часы компьютера должны быть синхронизированы. Нельзя при повторе старого файла подставлять текущее время: это обойдёт защиту от отката. Намеренное восстановление старых цен — новый согласованный файл с новым временем изменения.

## Локальная проверка без production

```sh
npm run catalog:prepare-sync
npm run dev
```

Отдельный ключ и адрес находятся в `.catalog-sync/local-config.json`; тестовый прайс хранится в `.local-test-orders/catalog`. Локальный режим не использует Blob, Telegram и Google Sheets. Для отправки с этого Mac:

```sh
npm run catalog:upload-local -- 'public/Цены.xlsx'
```

Перед передачей IT проверить формат на копии корпоративного файла. Автотесты: `npm run test:catalog-sync`, `npm run test:orders`, `CI=true npm test -- --watchAll=false --runInBand`.

Полный изолированный HTTP-тест (нужен доступ к localhost): `npm run test:catalog-sync-http`. Он отправляет Excel с тестовой переоценкой, читает цены после сохранения/перезапуска и оформляет локальный заказ с отметками `not_sent` для внешних сервисов.

## Ограничения

Если офисный компьютер выключен, файл недоступен или выгрузка не удалась, остаются последние успешно сохранённые цены; расписание и уведомления на стороне IT обязательны. Нет обещания обновления в конкретную секунду. Файлы старого прайса не архивируются в Blob; хранится только текущий нормализованный снимок цен. Внутренний исходный Excel целиком в интернете не публикуется. Заказы и защита от дублей не меняют свой формат; история прошлого заказа в браузере не очищается.
